# PowerPC 602 Architecture and Diab Data ABI (`dcc` 3.7a)

The 3DO M2 (FZ-35 / Bulldog) platform uses a dual-CPU **Motorola/IBM PowerPC 602** configuration coupled to the Bulldog custom ASIC. *IMSA World Championship Racing* (`driving/game`), its launcher (`LaunchMe`), the companion game (`shooter2d/shooter2d`), and all Portfolio OS v3.0 modules were compiled with the Diab Data C/C++ Compiler (`dcc`) Release 3.7a targeting 32-bit big-endian PowerPC EABI.

## Hardware CPU and Time Base Topology

| Parameter | M2 Hardware Specification |
|---|---|
| **Processors** | 2 × PowerPC 602 (CPU 0 = Master, CPU 1 = Slave) |
| **Core Clock** | `66.666667 MHz` (2× bus multiplier) |
| **System Bus Clock (`bg_BusClock`)** | `33.333333 MHz` |
| **Time Base Frequency (`bg_TicksPerSec`)** | `bg_BusClock / 4 = 8,333,333.25 Hz` (`~120 ns` per tick; `124,999` ticks per `15,000 µs` scheduler quantum) |
| **Byte Order** | 32-bit Big-Endian (`MSR[LE] = 0`) |
| **Hardware FPU** | **Single-Precision Only** (32 × 32-bit FPRs `fr0..fr31`; IEEE-754 single-precision arithmetic) |
| **Caches** | 4 KB 2-way instruction cache + 4 KB 2-way data cache (`32-byte` cache lines) |

### Master vs. Slave CPU Identification (`SR14`)

Portfolio OS distinguishes CPU 0 (Master) from CPU 1 (Slave) using PowerPC Segment Register 14 (`SR14`). In `IsMasterCPU` (`0x66fc0`), the guest executes:

```powerpc
mfsr    r3, 14          # Read SR14 (0 on Master CPU, non-zero on Slave CPU)
```

During race simulation, CPU 0 runs the Portfolio OS kernel, game state machine, audio/FMV threads, and Mercury 3D command list submission, while dispatching vehicle physics (`CarSimFunction`) and visibility/lighting batches (`SlaveFunction`) to CPU 1 through the `mp` (`CMDC_MP = 0x106`) device.

## Architectural Registers and ABI

The table below lists the PowerPC 602 user-state registers and Diab EABI calling conventions (see [Guest Runtime](../recompilation/runtime.md#runtime-ownership-architecture) for the subset stored in `PPCContext`).

| Register Group | Width | ABI Role & Conventions |
|---|---|---|
| `r0` | `32-bit` | Volatile scratch; reads as literal `0` in base-register addressing modes (`addi`, `lwz`, `stw`, etc.). |
| `r1` (`SP`) | `32-bit` | Stack pointer; 16-byte aligned, grows downward via `stwu r1, -N(r1)`. |
| `r2` | `32-bit` | Unused (`0` memory references in `driving/game`; Diab EABI does not use an AIX TOC). |
| `r3 .. r10` | `32-bit` | Volatile integer/pointer argument registers (`r3` = 1st arg and 32-bit return value; `r3:r4` = 64-bit return value). |
| `r11, r12` | `32-bit` | Volatile scratch and prologue/epilogue linkage temporaries. |
| `r13` (`SDA`) | `32-bit` | Small Data Area base pointer (only 30 D-form references across `driving/game`; most globals use absolute `ha16`/`lo16` addressing). |
| `r14 .. r31` | `32-bit` | Non-volatile (callee-saved) general-purpose registers. |
| `f0` | `32-bit` | Volatile floating-point scratch register. |
| `f1 .. f13` | `32-bit` | Volatile floating-point argument registers (`f1` = float return value). |
| `f14 .. f31` | `32-bit` | Non-volatile (callee-saved) floating-point registers. |
| `CR` (`CR0..CR7`) | `32-bit` | Eight 4-bit condition fields (`LT`, `GT`, `EQ`, `SO` / `FX`, `FEX`, `VX`, `OX`). `CR0` is updated by integer `.` record forms (`cmpwi`, `addic.`, etc.); `CR1` is updated by floating-point comparisons (`fcmpu`, `fcmpo`). |
| `LR` | `32-bit` | Link Register (return address for `bl`, target for `blr`/`blrl`). |
| `CTR` | `32-bit` | Count Register (loop counter for `bdnz`/`bdz` and indirect call/jump target for `bctrl`/`bctr`). |
| `XER` | `32-bit` | Fixed-Point Exception Register: architectural bits 0 (`SO`), 1 (`OV`), and 2 (`CA`), corresponding to integer masks `1u<<31`, `1u<<30`, and `1u<<29`. |
| `FPSCR` | `32-bit` | Floating-Point Status and Control Register. |

## Diab Data `dcc` 3.7a Compiler Profile (`driving/game`)

Diab `dcc` code generation conventions in `driving/game` (`120,859` 32-bit instruction/literal words / `483,436` bytes of `.text` across `1,365` functions):

### Calling Convention and Hard-Float ABI

- **No Floating-Point GPR Spilling**: Floating-point parameters are passed exclusively in `f1..f13` without mirroring them into `r3..r10` unless the callee is variadic.
- **Leaf Functions**: `740` of `1,365` functions (`54.2%`) are frameless leaf functions that do not allocate a stack frame (`stwu r1, -N(r1)`) or spill `LR`.
- **Out-of-Line Millicode Register Save/Restore (Kernel Folio Vectors)**:
  Instead of linking compiler millicode into every executable, Portfolio OS exports Diab's register save/restore helpers directly from the Kernel Folio (`module 1`). The imported families are:
  - `_savegpr_14`, `_savegpr_17 .. _savegpr_27` (`1:489`, `1:492 .. 1:502`): Save `rN..r31` relative to `r11` (`r11` holds the caller's `SP`).
  - `_restgpr_14`, `_restgpr_17 .. _restgpr_27` (`1:381`, `1:384 .. 1:394`): Restore the same range.
  - `_savegprs_14 .. _savegprs_27_l` (`1:525 .. 1:538`): Save `r0` (`LR`) at `4(r11)` and `rN..r31` at negative offsets from `r11`.
  - `_restgprs_14 .. _restgprs_27_l` (`1:417 .. 1:430`): Restore `rN..r31`, load `LR` from `4(r11)`, restore `r1 = r11`, and return directly to the caller (`blr`).
  - `_savefprs_21_l .. _savefprs_28_l` (`1:460 .. 1:467`) and `_restfprs_21_l .. _restfprs_28_l` (`1:352 .. 1:359`): Save/restore non-volatile single-precision FPRs `fN..f31` using `stfs`/`lfs` (4 bytes per register).

### Software Helper Intrinsics (Kernel Folio Vectors)

Because 32-bit PowerPC lacks a direct GPR-to-FPR move instruction and the PPC602 FPU is single-precision, Diab `dcc` emits calls to Kernel Folio intrinsics for type conversions and variadic marshaling:

| Kernel Ordinal | Symbol | Call Sites in `driving/game` | Behavior |
|---|---|---|---|
| `1:325` | `__itof` | `201` | Converts signed 32-bit `int32_t` in `r3` to `float` in `f1`. |
| `1:326` | `__utof` | `55` | Converts unsigned 32-bit `uint32_t` in `r3` to `float` in `f1`. |
| `1:267` | `__va_arg` | Variadic helpers | Steps a Diab `va_list` descriptor and returns a pointer to the next argument in `r3`. |
| `1:89 .. 1:91` | `__tagCall_0`, `__tagCall_1`, `__tagCall_2` | TagArg VA stubs | Converts variadic `TagArg` arguments on the stack into a `const TagArg *` array pointer and tail-calls the non-VA Folio vector. |

### Relocatable Modules

The executables use 3DO/Diab ELF32 relocation records in `.rela.text` and `.rela.data`. Absolute `ha16`/`lo16` pairs, data pointers, and image-local folio imports are relocated before execution (see [Relocation Resolution](../recompilation/translation.md#relocation-resolution)).

## PowerPC 602 Instruction Semantics and Edge Cases

### Single-Precision FPU and Fused Multiply-Add

`driving/game` is a pure single-precision workload:
- `8,064` `lfs` and `4,130` `stfs` instructions (`0` `lfd` and `0` `stfd` instructions).
- `1,606` fused multiply-add instructions (`fmadds`, `fmsubs`, `fnmadds`, `fnmsubs`).
- **`fsel frD, frA, frC, frB` (`76` sites)**: Selects `frC` if `frA >= 0.0f`, else `frB`. Because comparison uses IEEE-754 rules, `-0.0f` satisfies `>= 0.0f` and selects `frC`, while `NaN` fails `>= 0.0f` and selects `frB`.
- **`frsqrte frD, frB`**: Computes a single-precision reciprocal-square-root estimate refined by the caller (see [Reciprocal-Square-Root Accuracy](#reciprocal-square-root-accuracy-and-open-hardware-questions) below).

### Condition Register Bit Operations (`crxor`, `cror`, `crand`, `crnor`, `crorc`, `crandc`)

The Mercury 3D engine (`M_Draw.c`, `M_Clip.c`) packs per-vertex frustum plane clip flags directly into `CR` bits and combines them with condition-register logical instructions (`cror`, `crand`, `crandc`, `crnor`, `crorc`, `crxor`). Bit indices `0..31` map MSB-first across `CR0..CR7` (`bit / 4` selects field `CR0..CR7`; `3 - (bit & 3)` selects its bit within the field).

### Carry (`XER[CA]`), Shift Clamping, and Record-Form Aliasing

- **`addic` / `addic.` with Negative Immediates**: PowerPC sign-extends the 16-bit immediate to 32 bits (`uint32_t imm = (uint32_t)(int32_t)(int16_t)simm`) and computes unsigned 32-bit carry out (`(uint64_t)rA + (uint64_t)imm > 0xFFFFFFFFULL`). For example, `addic rD, rA, -1` sets `XER[CA] = (rA != 0)`.
- **`subfic rD, rA, SIMM`**: Computes `~rA + sext(SIMM) + 1` and sets `XER[CA] = ((uint32_t)rA <= (uint32_t)(int32_t)(int16_t)SIMM)` (PowerPC inverted no-borrow carry). Specifically, `subfic rD, rA, 0` sets `XER[CA] = (rA == 0)`, which Diab `dcc` uses before `adde` to materialize boolean equality predicates.
- **`sraw rD, rA, rB` & `srawi rD, rA, SH`**:
  - In `sraw`, shift amounts come from `rB & 0x3F` (`0..63`). Shifts of `32..63` fill `rD` with the sign bit of `rA` (`rA >> 31`) and set `XER[CA] = (rA < 0)`.
  - Shifts of `1..31` set `XER[CA] = 1` iff `rA < 0` **and** any shifted-out low bit is `1` (`(rA & ((1u << sh) - 1)) != 0`).
- **Record-Form (`.`) Destination Aliasing**: Instructions with `Rc = 1` (such as `addic.`, `subf.`, `and.`, `srawi.`) evaluate inputs and `XER[CA]` using the pre-instruction value of `rA`/`rB` before writing `rD` and updating `CR0`, since `rD` frequently aliases `rA`.

### Computed Intra-Function Returns in Mercury Clipper (`M_Clip.c`)

In the Mercury frustum clipper (`M_SaveClippedLitTex` at `0x558d4`, `M_ClipEnvLitTrans` at `0x567f8`, `M_SaveClipped` at `0x57268`), the guest loads an intra-function continuation address into `r23`, calls a plane-clipping block, and returns to the continuation via `mtlr r23; blr`. The static recompiler detects `mtlr` combined with known intra-function code labels and dispatches `blr` through the function's internal label switch whenever `ctx->lr` matches an internal continuation address.

## Reciprocal-Square-Root Accuracy and Open Hardware Questions

The [PowerPC 602 User's Manual](https://zxgit.org/RomanRom2/awesome-cpus/raw/commit/8115b6c97d547c13037b0cfcb0125d09a3e90543/PowerPC/PowerPC_602/manual.pdf) (Table 2-24, page 2-43) specifies that `frsqrte` produces a single-precision estimate with relative error $|e| \le 1/32$, but does not publish the internal ROM lookup table coefficients. Neither the public M2 SDK math routines ([`rsqrtf.S`](https://github.com/trapexit/portfolio_os_m2/blob/master/ws_root/src/libs/spmath/rsqrtf.S), [`rsqrtff.S`](https://github.com/trapexit/portfolio_os_m2/blob/master/ws_root/src/libs/spmath/rsqrtff.S), [`rsqrtfff.S`](https://github.com/trapexit/portfolio_os_m2/blob/master/ws_root/src/libs/spmath/rsqrtfff.S)) nor PowerPC 603/750 tables (such as Dolphin's [`FloatUtils.cpp`](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/Common/FloatUtils.cpp)) establish the exact 602 seed table.

In `driving/game`, callers refine the `frsqrte` seed differently: `sqrtf`/`sqrt` (`0x4aca0` / `0x4acb4`) and Mercury vertex lighting (`M_Draw.c`) apply standard Newton-Raphson iterations, whereas point and spot light reciprocal-distance paths use a single custom correction step. The [host `ppc_frsqrte` helper](../recompilation/translation.md#floating-point-implementation) satisfies the architectural $1/32$ relative error bound and IEEE special-value rules, though final low-order mantissa bits in unrefined or single-step paths may differ slightly from physical 602 silicon until a hardware bit-pattern dump is captured.
